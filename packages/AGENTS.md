# packages

Shared code. Packages never import an app or a module. Each exposes its TypeScript source from `index.ts` (`main`, or `exports` when it has subpaths), extends `@domus/tsconfig/base.json` and has a `type-check` script; only the apps build. A package with tests adds `test` and a `vitest.config.ts`.

- `platform`: the door (`http`: `createHttpHandler`), `actions` (the one path of every action: validate, authorize, run; a write also needs its key and runs in one transaction with its log entry; the same key and request again returns the stored result after authorizing anew, another request under it is a `key-reused` conflict; `undo` runs the inverse an entry stored, with its own key, if no later entry touched its records, and logs one new entry linked both ways), `authorization` (the only decision; denies everything in production until 1c), `audit` (the action log over `platform/0001`, prepared statements, never commits), jobs and scheduled tasks, events, notifications, storage. The rest is built in phase 1. `@domus/platform/testing` holds a module's raw Drizzle client (`moduleDatabase`), a platform with a given authorizer and clock, `invokeAction`, `undoEntry` and `readLog`; only `test-utils` may import it (ADR 0021, ADR 0022).
- `platform/contracts` (`@domus/platform/contracts`): the platform's own contracts, such as `status` and `PROTOCOL`. Pure: no Node, no other part of platform. The only part of platform that `web`, `assistant` and `voice-gateway` may import.
- `module-sdk`: the only part of platform a module may use: `defineModule` (tables, migrations, `contract` and `actions`) and `checkModules`; `@domus/module-sdk/db` re-exports what a module needs of Drizzle and adds `moduleTables(id)` and `id()` (ADR 0021); `@domus/module-sdk/contracts`, pure, offers `readAction` and `writeAction({ undoable })` (ADR 0022). A module gets its database only from a handler's context.
- `ui`: the design system, Vue components (phase 2).
- `i18n`: translation runtime and catalogs.
- `utils`: one business-free topic per folder, imported as `@domus/utils/<topic>`. A topic enters when it knows nothing of the business and two places use it; a topic imports another only through a named exception in `.dependency-cruiser.cjs`. Topics: `connection` (connecting, ready, incompatible, with a 10 s limit per check); `program` (port and address reading, the `/health` server, shutdown on signals); `date-time` (`date-fns`, `Intl`) comes in phase 1.
- `test-utils`: what tests use instead of real infrastructure: `createTestPlatform`, a real platform in memory or on a file with the door in process (the only path the rules give the tests of `assistant` and `voice-gateway` to it), a programmable authorizer, a controllable clock, synthetic actors, a typed `invoke` (a write takes its key and returns its result and entry number), `undo(actor, entry, { key })` and `log()`; later the fake model and fake channel. Only tests import it.
- `api-client`: `clientFor(contract, transport)`, a thin oRPC link. It holds no contract: callers pass theirs. Authentication and retries belong to the caller.

`utils`, `i18n`, `ui` and `api-client` know nothing of platform, its contracts included.
